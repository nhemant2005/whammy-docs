# Issue 16.4 — Gradient layer: Tea Green → Periwinkle fill synced to generation progress

**GitHub:** #20
**Label:** done
**Blocked by:** Issue #19 (16.3)

## What was built

Added a fixed full-viewport gradient layer to `preview.html` that reveals from bottom to top in sync with section generation progress, and sits fully revealed when docs already exist.

**HTML — first child of `<body>`:**
```html
<div id="gradient-layer"></div>
```

**CSS (in `<style>` block):**
```css
#gradient-layer {
  position: fixed;
  inset: 0;
  z-index: 0;
  pointer-events: none;
  background: linear-gradient(to top, var(--color-accent), var(--color-primary));
  clip-path: inset(calc(100% - var(--gradient-progress, 0%)) 0 0 0);
  transition: clip-path 600ms ease-out;
  opacity: 0.18;
}
```

Note: `opacity: 0.18` was added (not in original spec) to prevent the full-saturation Tea Green → Periwinkle gradient from overwhelming the Jet Black surface. At 18% opacity it reads as an ambient glow without washing out text.

All page content is at `z-index: 1` (main `<div>` has `position: relative; z-index: 1`); the gradient sits beneath.

**JS — `--gradient-progress` management:**

Initialisation (before any SSE):
```js
// generating mode
document.documentElement.style.setProperty('--gradient-progress', '0%');
// preview/done mode
document.documentElement.style.setProperty('--gradient-progress', '100%');
```

On each `section-complete` SSE event (inside `setSectionDone`):
```js
const pct = Math.round((completedCount / KNOWN_TOTAL) * 100);
document.documentElement.style.setProperty('--gradient-progress', `${pct}%`);
```

On `done` SSE event:
```js
document.documentElement.style.setProperty('--gradient-progress', '100%');
```

The Jinja `{% if generating %}` block controls which branch runs at page load, so no flash of wrong state.

**Test added to `tests/test_theme.py`:** `test_gradient_layer_present_in_preview` — creates a session, asserts `id="gradient-layer"` present in both the generating state (no docs) and the done state (docs exist).
