## Project: WhammyDocs

AI-powered documentation generator. Developer uploads a `.zip` of their project, gets a complete MkDocs documentation site (README, API reference, architecture overview, guides) generated by AI — previewed, editable, and downloadable.

**Hackathon deadline:** May 24, 11:59 PM IST. GitHub repo: `whammy-docs`.

## Tech Stack

- **Backend:** FastAPI (Python) — serves UI and AI pipeline
- **Frontend:** HTMX + Tailwind CSS + Jinja2 templates (no JS framework)
- **AI:** DeepSeek Flash API (`$0.50/M` input tokens)
- **Docs output:** MkDocs + Material theme (builds static HTML)
- **Markdown preview:** `marked.js` in browser
- **File handling:** Python `zipfile` module

## Commands

```bash
# Install dependencies
pip install fastapi uvicorn python-multipart jinja2 mkdocs mkdocs-material

# Run dev server
uvicorn main:app --reload

# Build MkDocs site from generated markdown
mkdocs build --config-file /tmp/<session>/mkdocs.yml
```

## Architecture

### Request Flow

```
POST /upload   → save & extract zip → scan files → call DeepSeek per section
               → store section→file mapping → build MkDocs site → return preview page

POST /edit     → apply local edit (no AI call) → return updated HTML

POST /regenerate → read only mapped source files → narrow DeepSeek call → merge into docs

GET /download  → zip the site/ folder → return site.zip
```

### Section-to-File Mapping

Each generated doc section stores metadata linking it to its source files. Regenerating a section only re-sends those files to the LLM — not the full project.

```
api-reference.md  →  [routes/auth.py, routes/users.py, ...]
readme.md         →  [full project scan]
architecture.md   →  [project structure scan]
getting-started.md → [readme, config files, requirements.txt]
```

### Generation Modes

- **Comprehensive:** README + API ref + architecture + guides. Reads all source files. ~30–60s.
- **Quick:** README + API ref only from key files. ~10–20s.

### Preview & Edit Screen

Sections rendered as collapsible cards:
- `marked.js` renders markdown → HTML in browser
- [Edit] → `contenteditable` textarea (no AI call, local only)
- [Save] → stores edit locally
- [Regenerate with AI] → `POST /regenerate` with section's file mapping

### Language Detection

Via file extension scan. Prompt adjusts per detected language (Python, JS, TS, Java, Go, Rust, Ruby, PHP, C++, C#, Shell). All languages share the same pipeline.

### File Upload

- Standard `<input type="file" accept=".zip">` with HTML5 drag-drop
- FastAPI `UploadFile` → saves to `/tmp/` → extracts with `zipfile`
- No third-party upload libraries (FilePond/Uppy deferred)

### Conventions
- All routes stay in `main.py` (no routers sub-package — app is small enough)
- Business logic goes in `scanner.py` or `generator.py`, not inline in routes
- Every new module gets a matching test file in `tests/`
- Session data lives in `/tmp/whammy-<session_id>/` — no DB, no global state

## Key Constraints

- No user accounts or persistent storage — everything is session/tmp-based
- No GitHub URL integration (manual zip upload only for MVP)
- Single MkDocs Material theme — no theme selection
- Cost per generation: ~$0.03–0.05 in DeepSeek API calls
